# 重命名执行计划：student → child / 学生 → 小孩

> 版本: v1.0 | 日期: 2026-06-22 | 关联 PRD: v2.1.0 模块 11（家长角色 MVP）

## 决策记录

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 数据库表名/字段名 | **不改** | 零迁移风险；SQL 保持 `students`/`student_id`/`student_answer`；代码注释标注 |
| 错题 UI "学生答案" | → **"作答"** | 唯一例外，更自然 |
| 执行策略 | **一次性全改** | 独立分支 `refactor/student-to-child`，单独 PR |
| Pinia store ID | `"students"` → `"children"` | 加 localStorage 迁移兼容 |
| Tauri command 名 | **不改** | `sync_students` 等保持原样，前端 invoke 不变 |
| 备份包兼容 | `state.students ?? state.children` | 旧备份可恢复 |
| 历史文档（需求记录.txt 等） | **不改** | 保留原始记录作为来源参考 |

### 2.8 Pinia Store ID 迁移

`defineStore` 第一个参数从 `"students"` → `"children"` 会导致 localStorage key 变化。需在 `childStore.ts` 的 `setup()` 开头加迁移逻辑：

```ts
// Pinia persist 迁移：旧 key "students" → 新 key "children"
const OLD_KEY = "students";
const NEW_KEY = "children";
const raw = localStorage.getItem(OLD_KEY);
if (raw && !localStorage.getItem(NEW_KEY)) {
  localStorage.setItem(NEW_KEY, raw);
  localStorage.removeItem(OLD_KEY);
}
```

### 2.9 备份包兼容

`workspaceBackup.ts` 中读取备份时加 fallback：

```ts
const students = state.students ?? state.children;
```

写入时使用 `children` key（新格式）。
